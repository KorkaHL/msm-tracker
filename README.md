# 🎵 MSM Tracker

Telegram-бот и сайт с расписанием событий **My Singing Monsters**: активные и предстоящие события,
что они значат для игрока, окна доступности монстров, прогноз по прошлым годам и уведомления.
Работает **целиком на GitHub** (Actions + Pages), без сервера и без ручного заполнения.

## Как это работает

```
 Fandom wiki (MediaWiki API)
        │  каждые 3 часа (data.yml)
        ▼
  msm.pipeline ──► data/events.json ──► GitHub Pages (site/)
   • события из категорий/страниц-списков/инфобоксов/текста
   • прогноз: даты прошлых лет → следующий год (🔮, с уверенностью)
   • «что это значит»: теги и объяснения по ключевым словам
   • расписание монстров: ссылки на монстров из событий + строки «available…» на страницах монстров
   • защита: если парсер вдруг нашёл 0 событий или вдвое меньше — файл НЕ перезаписывается,
     workflow падает (GitHub пришлёт письмо) + опциональный алерт в Telegram админу
        │
        ▼
  bot.yml: каждые 5 мин стартует задача, ~5.5 мин держит long polling
  (ответы почти мгновенные), рассылает уведомления, сохраняет состояние
  в ветку bot-state (файл зашифрован ключом STATE_KEY — репозиторий публичный)
```

Команды: `/now` `/soon` `/shop` `/event <название>` `/monster <имя>` `/settings` `/tz` `/about`.
Свободный текст = поиск события. Уведомления (включены по умолчанию, настраиваются в `/settings`):
новый анонс · старт · конец через 24 ч · монстр появился в магазине. Прогнозы 🔮 уведомлений не вызывают.

## Запуск (≈10 минут)

1. Создай бота у [@BotFather](https://t.me/BotFather), получи токен.
2. Репозиторий должен быть **публичным** (иначе лимит бесплатных минут Actions съест постоянный бот).
3. `python -m msm.cli gen-key` → ключ шифрования состояния.
4. Settings → Secrets and variables → Actions, добавь секреты:
   `TELEGRAM_TOKEN`, `STATE_KEY`, (необязательно) `ADMIN_CHAT_ID` — твой chat_id для алертов о сломанном парсере.
5. Settings → Pages → Source: **GitHub Actions**.
6. Actions → *Update data & deploy site* → Run workflow (создаст `data/events.json` и сайт).
7. Actions → *Telegram bot* → Run workflow (дальше стартует сам по cron).

## ⚠️ Обязательная первая проверка парсера

Структуру вики и названия категорий я не мог проверить вживую (при разработке не было доступа к Fandom),
поэтому `config/sources.json` — обоснованное предположение, а парсеры — эвристики общего вида
(инфобоксы, таблицы, диапазоны дат в тексте), покрытые тестами на синтетических фикстурах.
Прогони у себя:

```bash
python -m msm.cli probe --search "event"
```

Команда покажет реальные категории вики и первые 40 найденных событий с источником каждой даты.
Подправь `event_categories`, `event_pages`, `list_pages` (страницы-таблицы), `monster_categories` — и всё.

## Ограничения

- Задержка GitHub cron: при нагрузке Actions старт задач может сдвигаться на минуты; бот-job
  стоит в очереди, поэтому провалы короткие, но возможны.
- Даты событий берутся с точностью до дня (UTC). Точное время старта в вики обычно не указано.
- Прогнозы — статистика по прошлым годам, не официальный анонс.
- Описания берутся из вики на английском; «что это значит» — русские пояснения по тегам.
